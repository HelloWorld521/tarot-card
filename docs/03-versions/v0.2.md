日期：2026-11-07

## 这个版本做了什么

结果页多了一个「生成分享卡」按钮。点开后生成一张 **1080×1440** 的竖版 PNG，在页面内用浮层预览，并提供保存方式。

图面顺序（自上而下）：

1. 顶部一行小字「恋人 · 角色卡」；
2. 头像（现成的哈希色块 + 首字）与名字；
3. 三个品质大字竖排，140px 衬线体，占画面主体；
4. 一句钩子「这三个词，你敢签吗」；
5. 底部二维码 + 短网址文字 `helloworld521.github.io/tarot-card`；
6. 命中矛盾体时，右上角多一个小标记。

硬约束：图上只露正面。`share.js` 只读名字、头像色、三个品质名与钩子，代码不访问 `costLabel`、`backScene`、`comboText`、弱维句，所以代价信息不可能出现在图里。

保存方式：

- 桌面端点「保存图片」走 `<a download>`，文件名 `lover-card-<名字>.png`。
- iOS Safari 检测到后显示「长按图片，保存到相册」；图片保留 `-webkit-touch-callout: default` 与可选中，长按能唤起系统相册菜单。
- 浮层可用「收起」、点背景、Esc 关闭；打开时锁页面滚动。

实现要点：

- 用 Canvas 2D 手绘，不截图 DOM、不引第三方库，避免跨设备渲染差异。
- 内部按 2× 超采样（2160×2880）绘制，再高质量缩放到 1080×1440，导出尺寸固定、小字不糊。
- 字体栈：`Songti SC → STSong → Source Han Serif SC → Noto Serif CJK SC → Noto Serif SC → serif`，字距由逐字绘制控制。
- 二维码是自己写的最小编码器（`qr.js`）：byte 模式、版本 1–3、纠错等级 M、单块 Reed-Solomon、8 种掩码按罚分择优、15 位 BCH 格式信息。
- 新增文案全部进 `data/config.js` 的 `copy.share` 段（按钮、标题、顶部小字、钩子、矛盾体、二维码地址与显示文字、保存按钮、iOS 提示、文件名前缀、收起按钮）。

## 已知问题

- iOS 的长按保存提示只在代码层做了 UA 判断与样式放开，没有真机验证；不同 iOS 版本长按菜单的文案可能不同。
- 分享图不含代价与组合文案，这是设计决定，不是缺陷；如果未来要做「背面版」分享图，需要重新走一轮决策记录。
- 本地 `main`（`a10427c`）与远端（`696f2d4`）内容相同但 SHA 不同。下次在本地继续开发前，先 `git fetch origin && git reset --hard origin/main`，否则会分叉。
- `qr.js` 只支持版本 1–3、纠错 M，短网址上限约 42 字节；如果以后换更长的地址，需要扩展版本或直接退化到只显示网址文字。
