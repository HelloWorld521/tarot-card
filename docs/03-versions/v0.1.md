# v0.1 · 第一版：能完整建一张卡

日期：2026-11-07
状态：完成并验证

## 这个版本做了什么

一条能从头走到尾的建卡流程，共 7 个界面：

1. **起始页**：标题 + 「开始」；顶栏右侧是通讯录入口与已存卡数量。
2. **关系页**：只有「恋人」可选；朋友、同事是灰态，标注未解锁，点了没反应。
3. **名字页**：输入名字后，头像实时预览——名字哈希出 HSL 色相，取首字作为字面。空名字时「继续」不可点。
4. **选卡页**：12 张牌正面朝上，只显示罗马数字、品质名与正面场景。选中的牌上浮、描金，再点一次取消。底部显示 `已选 n/3` 与三个菱形点，选满 3 张才能继续；点第 4 张会被拒绝（抖动 + 提示），不会写入数据。
5. **翻面页**：三张牌依次翻面，每张间隔约 680ms，显示背面场景与代价标签；全部翻完后才出现「看结果」。
6. **结果页**：名字、头像、关系、三个品质、三个代价标签，命中组合时显示组合文案，命中 `paradox` 组合时显示「矛盾体」标记，最后一句是按四维权重算出的弱点台词。底部三个动作：存入通讯录、重新建一张（v0.2 之后多了生成分享卡）。
7. **通讯录**：无卡时是空状态说明；有卡时是一叠牌（最多 3 张虚影 + 一张焦点卡），左右可切换、点击像抽出一张，进入详情浮层；详情里可以删除，删除需要二次确认。

配套能力：

- 卡与通讯录都存在 `localStorage` 的 `tarot-lover-cards-v1` 键，刷新后仍在；存储不可用时弹提示，不崩溃。
- 数据全部在 `data/`：12 张卡（`traits.js`）、10 组组合（`combos.js`）、文案与兜底模板（`config.js`）。
- 兜底：三张卡没命中任何组合时，用 `config.copy.fallback` 的三句模板，以 `{first}` / `{second}` / `{third}` / `{cost2}` / `{cost3}` 填充。
- 弱点句：`security` / `space` / `stability` / `intensity` 四维求和取最低维，代入 `config.weakSentence`。
- 轻音效：选择与翻面用 WebAudio 合成正弦音，失败时静默，不阻塞流程。

## 怎么验证的

启动方式：

```bash
cd /Users/hujiayu/Code/tarot-card
python3 -m http.server 8000
```

用 Playwright（Chromium headless）在 390×844 的移动视口跑完整流程，断言包括：

- 12 张卡渲染正确、关系页灰态正确、头像首字正确；
- 选满 3 张后「继续」才可点；点第 4 张被拒绝且出现提示；取消一张后按钮回灰，补回第三张恢复；
- 三张牌全部翻面后「看结果」出现；结果同时包含名字、3 个品质、3 个代价标签；
- 存入后按钮变为「已存入 · 查看通讯录」，`localStorage` 数组长度为 1；
- 刷新页面后顶栏仍显示 1 张、通讯录仍能看到该卡；
- 删除走二次确认，删完回到空状态且 storage 清空；
- 专一 + 自由 + 诚实 → 矛盾体标记 + 对应组合文案；
- 诚实 + 上进 + 自由 → 走兜底三句 + 弱点句 + 无矛盾体；
- 390 宽无横向溢出、无 JS `pageerror`；1280 宽桌面端 12 张卡排布正常。

另用截图人工检查了起始页、选卡、翻面、结果、通讯录、详情、两卡叠牌与桌面端，修掉了三处布局问题：卡背纹样覆盖、叠牌虚影不可见、桌面端选卡页过高被底栏遮挡。
