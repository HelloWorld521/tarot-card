日期：2026-11-07（2026-11-08 得分区间改为按实际分布标定、四张新卡改名为 大度 / 干净 / 节俭 / 主动、组合扩到 24 组并改为命中内随机）

## 这个版本做了什么

- 卡池从 12 张扩到 16 张：新增「大度」「干净」「节俭」「主动」，编号补齐到 `XVI`。四张新卡仍遵守「同一场景两种走法」，代价短标签保持短词量级；2026-11-08 把这四张的场景与代价文案改写为更具体的画面（如「隔夜一句吃饭了」「随手放个杯子被念三天」）。
- 结果页新增总分与四维分项：单维原始和 -9～9 先映射为 0～25 的原始分，四维原始总分按实测锚点 51→80、71→100 线性拉开并钳制；四维分项以 20 为底、按各维原始分占比分摊总分，最大余数法保证四项之和严格等于总分。
- 组合扩到 24 组：现有 10 组重写为能看出四维张力的具体场景，四张新卡各补 3 组，另补 2 组原有卡的高张力搭配。三张牌命中多条组合时随机取一条，数组顺序不再影响结果；兜底模板不变。
- 分享图新增总分一行，位置在左上角；仍然只露正面，不画四维分项与任何代价。
- 数据拆成三份：`data/traits.js`（卡身份 + 四维 + 场景引用）、`data/scenes.js`（正面 / 代价 / 背面文案）、`data/combos.js`（组合）。三份只靠 id 关联，改场景或组合不需要碰品质卡。
- 历史卡片兼容：旧卡缺 `scores` 字段时正常显示，只是不显示得分；不清空、不覆盖原有通讯录。

随机匹配实测：选大度 + 干净 + 自由（同时命中 3 条组合），把 `Math.random` 固定为 0 时得到「两个人都能接受散场……」，固定为 0.999 时得到「吵完架他先把地上的碎玻璃扫干净……」，说明结果不再由数组顺序决定。

## 已知问题

- 分布中段厚、两端薄：90～95 占了大多数，80/81/82/100 各只有 2～4 种组合；极端分需要刻意凑特定卡才会出现，分数仍只作相对参考。
- 得分锚点（51/71）与当前卡牌数值强耦合。以后改任何一张卡的 `axes`，都必须重跑 560 种组合并同步 `config.scoring` 的两个锚点，否则分布会重新挤在一起。
- 组合改为命中内随机后，同一组三张牌重复建卡可能得到不同组合文案；`randomIndex` 是唯一随机入口，以后要做可复现测试需要在这里替换成种子函数。
- 旧卡不补算得分。即使它的品质 id 仍存在，也不显示分数，避免用新规则改写历史数据。
- 新增卡使移动端选卡页变为 2 列 × 8 行，桌面端最后一行为 4 张；这是数量变化的直接结果，未调整网格列数。
